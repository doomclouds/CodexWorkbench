# 工程与交付约定

## Windows 与 macOS

两端都是正式目标。常规 JS 使用一套实现，不为普通页面、数据处理和 Node API 引入平台判断。

实际涉及操作系统的部分再隔离适配，例如原生模块、系统文件选择器、凭据存储和进程管理。此时检查依赖的 Windows／macOS 支持及需要交付的 CPU 架构，不用未经验证的“JS 项目天然跨平台”代替证据。

- 构建与打包脚本优先使用 Node.js；不让开发流程依赖 PowerShell-only、Bash-only 命令或开发机全局工具。
- 用 Node 路径 API 处理本地路径，用 URL API 处理 URL；文件路径不直接拼成 URL。
- 不硬编码盘符、用户名、路径分隔符或源码目录外的参考仓库位置。
- 文件命名与 import 大小写保持一致；用户选定的数据目录允许空格、中文及其他 Unicode 字符。
- 需要启动外部程序时传递参数数组，管理超时、取消与退出；不要把用户输入拼成 shell 命令。
- 在对应系统的用户数据／配置目录保存运行数据，允许用户为内容库选择目录。源码、插件安装目录与可写数据目录分别处理。

这些检查集中于真实边界，避免给纯界面修改增加无关平台工作。

## 工具与数据操作

- MCP 工具声明有意义的参数、输出结构和读写副作用；注解是描述，不代替后端授权和输入校验。
- 列表分页或限制结果大小，长文本和大文件按需读取；不要把整个知识库一次送入模型上下文。
- 结果中使用稳定 ID、来源和定位信息，使 Agent 可以继续读取、验证或引用。
- 对可重试写入考虑幂等，对并发编辑使用合适的版本检查，避免静默覆盖用户修改。
- 耗时操作按需要提供任务 ID、状态、进度和取消；明确关闭页面或退出宿主后是否继续。
- 文件访问约束到用户选择或授权的范围，处理真实路径和符号链接边界；UI 隐藏按钮不代替后端检查。
- 本地 Web 服务默认限制本机访问，明确端口、启动和退出方式；需要对外访问时另行设计连接与认证。
- stdout 留给 stdio 协议，日志使用 stderr 或日志文件。日志不记录密钥和无关的完整用户内容。

## 界面约定

共享语义主题、基础控件和常见交互。新增组件库先检查现有共享组件与宿主样式能力，避免各插件维护一套不同的按钮和表单。

考虑加载、空状态、错误、重试、保存中和保存失败。Thread 面板适应窄宽度，操作支持合理的键盘路径与焦点反馈。不同入口可以调整布局，不必强行复制相同页面结构。

不把后端协议、SDK 参数和构建细节显示在普通业务流程中；用户需要处理连接或故障时再提供可操作的诊断信息。

## 依赖与代码变更

- 遵循仓库已有实现，补齐功能所需的最小修改。发现真实共享需求后再提取公共代码。
- pnpm 管理统一锁文件；可执行项目声明实际依赖，不依赖其他包偶然提升到根目录的依赖。
- 不通过运行 `latest` 的临时安装命令隐含升级整个项目；升级时核对使用中的版本与兼容关系。
- 依赖的许可证、原生模块、Worker／WASM 与最终包加载方式影响交付时，纳入选型说明。
- 重要的新运行时、共享服务、数据格式或公开契约变更记录原因与迁移影响。普通实现细节无需逐一写决策文档。

## 检查与测试

实际建立运行代码时，提供清楚区分的格式检查、lint、typecheck、test、build 和包检查入口。命令只有在仓库实现后才能报告为已执行或可用。

测试关注关键行为：数据写入与恢复、迁移、并发、工具契约、路径边界、入口生命周期，以及用户与 Agent 共用的主要工作流。文案、轻量样式或纯规范修改不为凑覆盖率增加测试。

按插件声明的能力验收：

- Global：打开、再次打开、资源定位与应恢复的状态。
- Thread：切换对话、多实例、上下文与草稿的归属。
- File：打开、读取，声明可编辑时验证保存和冲突处理。
- Web：直接打开 URL、刷新与深链接、服务断开，以及使用中的 WebMCP／Annotation 能力。
- 主题：明暗切换及使用中的组件和嵌入内容。
- 平台：Windows 与 macOS 的安装包启动和主要工作流。

可以用 CI 或对应平台实机完成适当检查；只在 Windows 运行通过时，不宣称 macOS 已验证。报告已执行的检查与仍未验证的范围，不重复运行无新增价值的检查。

## 打包与版本

每个插件独立版本化与交付。最终包包含所声明的清单、入口、Skills、资源和实际运行依赖；开发依赖、缓存和用户数据不进入安装包。

从临时解包目录运行冒烟检查，验证不依赖源码工作区、未声明依赖或绝对路径。MCP App 的 HTML、字体、Worker、WASM 等资源按实际 CSP 和宿主加载方式核实。单文件 HTML 是常见构建方案，不把所有二进制资源强行内嵌当成全项目要求。

安装说明声明 Node 等外部运行条件；如改为自包含分发，验证每个目标平台实际使用的运行文件。配置中使用宿主支持的包根路径机制，不能直接引用开发机路径。

只在产物存在并验证后，将对应插件加入实际可安装目录。修改 marketplace 的源目录后，按宿主支持的流程刷新或重装，不直接编辑安装缓存。

用户内容、密钥、日志、`node_modules/`、构建输出和 `.codegraph/` 不提交。以当前任务授权范围进行本地打包、安装或远程发布，不把创建项目 Skill 当作发布授权。

## Git 与规范维护

新建分支默认使用 `codex/` 前缀。提交使用 Conventional Commits，scope 可用插件 ID；保持修改范围清楚。是否提交或推送按当前任务要求，不继承参考仓库的自动提交指令。

本 Skill 是当前项目开发基线。用户明确改变约定时，更新最接近该规则的文件，并检查其他参考是否冲突。尚未确定的具体插件功能、业务数据格式、精确依赖版本或组件库，在对应任务中讨论，不以占位决策提前锁定。
