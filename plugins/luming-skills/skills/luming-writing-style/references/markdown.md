# 让 Markdown 呈现真实的信息关系

先写明白意思，再选择呈现形式。让排版帮助读者顺读、比较和回查，保持文本自身的含义完整。

## 按关系选择形式

| 信息关系 | 合适的呈现 |
| --- | --- |
| 连续解释、论证、机制与叙述 | 连贯段落 |
| 没有执行顺序的并列事项 | 无序列表 |
| 有依据的先后步骤 | 有序列表 |
| 对象与属性对应、同维度比较 | 表格 |
| 精确代码、命令、配置或数据 | 标明语言的代码块，或行内代码 |
| 需要看清的结构、分支、时序或变化 | 图示与必要的正文解释 |

段落讲得通时可以保持段落。表格中的项目应能按相同维度比较；不要把几段连续论证硬塞进单元格。为了引用而给并列项编号时，说明编号用于定位。

先标明独立操作或条件分支，再分别交代流程。检查“每次”“依次”“以下步骤”等引导语，避免把备选分支连接成同一串动作。公共准备可以合写，各分支的结束条件仍要清楚。

## 让标题和目录帮助定位

成篇文档通常保留一个 H1，正文标题按真实层次递进。普通答复不必强设文章标题。标题说明主题或要回答的问题，篇幅不足以形成独立问题的细节放回段落。

操作标题写读者要完成的动作，比如「导入 CSV 文件」。参考条目用读者会在目录或搜索中查找的真实名称，比如「CSV 文件编码」或接口标识。把会影响使用的条件、例外和失败状态写在该条目内。单位、默认值和取值范围也放在对应对象旁，方便读者直接查阅。

默认不为短文编章节号。长文需要稳定引用时，可用阿拉伯数字和十进制层级；重排后同步目录、数量、锚点和引用。既有规则 ID、版本号、条款号与业务数值按原义保留。

标题里的先后、因果和范围同样属于内容断言，须有材料支持。不要用分隔符堆叠假层级，也不要仅为字号跳级。

## 让强调具有明确作用

加粗突出少数关键判断、条件或动作。警告放在受影响的动作附近，并写清触发条件与后果。去掉加粗、颜色和图标后，要求、建议和例外仍应由文字表达。

默认按语义适量使用 Emoji，可用于章节标题或正文，文档一级标题不加 Emoji；本次明确要求和文档已有约定优先。图标帮助识别信息，不用于凑数量或纯装饰。强调不会提高要求强度，完成标记不能暗示未发生的验证。

引号用于真实原话、界面文字、正在讨论的表达或拟写文案。上下文交代它的身份，不给普通名词层层加引号。正文默认用「……」，嵌套用『……』；已有一致样式时沿用。代码、数据和真实引语不随排版偏好改字符。

## 保持精确文本和引用可用

用行内代码标明必要的标识符、路径与短命令，代码块标明实际语言。不要把普通解释整段放进代码块。代码与配置的语义、转义、缩进及大小写依原契约保留。

链接文字告诉读者目标的作用。引用支撑相邻的具体判断；缺少来源时保留不确定性。材料仅给出路径而没有内容时，把它列为核对入口，不声称已确认其中细节。

图示只承担它能准确说明的一种关系。说明图中的关键含义，让正文与图相互对应；模块摆在一起并不自动解释协作，箭头也不能添加原材料没有的依赖或先后。

## 用自然语言调整呈现偏好

优先遵循本次明确要求，再沿用目标文档约定，最后采用默认。局部要求只影响指定部分。用户无需填写配置；需要沿用既有设置时，保持这些名称的含义：

- `quote_style`：`corner` 或 `double`，只调整正文引号样式。
- `emoji_enabled` 与 `emoji_positions`：决定是否允许图标，以及可用于章节标题 `section_heading` 或正文 `body`。
- `highlight_types`：硬边界 `redline`、重点 `focus`、风险 `warning`、完成条件 `completion`、可变项 `variable`、说明 `note`。
- `emphasis_density`：`light`、`balanced` 或 `high`，只调整强调密度。

语气、解释深度和类比使用分别由作者口吻、理解过程和阅读兴趣说明负责；呈现设置不改变这些内容，也不新增业务要求。
