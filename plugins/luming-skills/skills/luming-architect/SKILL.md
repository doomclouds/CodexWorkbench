# 工程设计

1. 核对目标和现状。从用户场景沿现有入口追踪调用方、状态所有者、公开接口和已有测试。说明哪些事实已核实，哪些仍会影响方案选择。
2. 比较可行设计。有实质取舍时，给出两种能满足同一目标的做法。比较各自涉及的工程、状态由谁维护、调用方要改什么、兼容和验证成本。推荐一套，并说明决定这个选择的依据。能用小实验回答的问题，按当前授权取证。
3. 给出可实施的范围。列明允许修改的工程或模块及各自职责，写清拟变更的接口、数据和可观察行为。给出对应的验收场景，以及哪些变化需要用户另行确认。
4. 按本轮授权推进。用户要先看方案时，交付方案后等待确认。用户已授权实施且关键取舍已定时，将同一份范围交给实现者。发现需要跨出已确认范围时，说明新增改动、必要性和影响，只就变化部分取得确认。可以继续推进不依赖该决定的授权工作。
5. 用方案复核结果。有实施交付时，对照实际 diff 和验证证据，检查改动是否落在确认的工程范围内，接口、状态归属和用户可见行为是否符合方案。
