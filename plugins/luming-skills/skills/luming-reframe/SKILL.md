# 把问题说准

从用户自己的文件、代码和原话开始。若同一描述可能指向不同问题，先列出两三个合理解释。每个解释给一个能准确命名它的术语，再说出哪项观察能把它和其他解释区分开。选择最符合材料的解释，说明理由。

1. 只选会改变问题理解或实现选择的术语，按影响从大到小排列。数量以说清问题为准，复杂主题可展开到 8 至 12 个。每个术语用一句通俗的话解释，并指出它对应用户原话中的哪一部分。给出一个确实这样使用它的项目、论文或系统及其链接，再举出掌握这个词后可以向助手提出的具体要求。
2. 有相邻领域的经验值得借用时，说明它能帮助解决哪一部分问题、类比从哪里开始失效，以及哪些术语值得带回当前问题。
3. 指出原描述遗漏了哪些会影响决策的事项。
4. 用核实过的术语重写用户的描述，保留原有的目标和约束。

逐个打开引用链接，确认来源确实在对应含义上使用该术语。删去无法证实的引文，不为凑数填词。
