# 鹿鸣 · Luming Studio

鹿鸣 · Luming Studio 是 CodexWorkbench 的本地设计创作插件。通过 Codex 对话旁的 MCP App 进入 Luming Studio 首页，创建白板、组织原生对象和 HTML Region，并围绕具体内容留下备注、附加到对话，让 Codex 修改原始内容。

白板可添加原生任务清单。选中后可逐行勾选、编辑、回车续加或重排，任务可保留来源。缩小后先看标题和完成进度，可主动展开查看内容。任务状态和每行的稳定 ID 随作品保存，支持按任务 ID 局部读取和更新。

白板还可放置文档区域：选中后可直接阅读、滚动和选择正文；文档标题栏的编辑、双击和 Enter/F2 统一进入展开编辑。展开后可按需打开目录、查找正文并返回原画布。标题、段落、列表、任务项、引用、表格、代码、图片和链接统一保存为块 JSON。右上角备注入口使用选中文字或段落，创建带块 ID 和来源版本的备注；Codex 按块修改，保留未涉及的正文与外框。文档只在编辑时启用完整编辑器，保存失败保留本机草稿，并提供比较当前内容后再保存。

文档区域的导出菜单提供全文 HTML 和块 JSON。完整作品 ZIP 备份保留文档与图片；单独文档 SVG／PNG 不作为全文格式。多人修改沿用文档对象版本检查，不是逐字实时同编。展开编辑使用插件工作区，退出恢复原画布视口与文档阅读位置。

文档默认纸张色与分区一致，可从选区格式条改填充色；正文、编辑、展开阅读和导出共用纸张配色。普通画布中的文档正文按区域宽度靠左排版，横向拉伸只改变可排版宽度，不缩放字号；展开阅读采用居中限宽。拖动标题栏、六点把手或正文下方的空白可以移动文档，拖动已选中文档中的文字可选择文字。边角用于调整尺寸。缩小画布时，文档标题栏和 HTML 区域标签随对象缩小。选中文档后也可从选区工具栏展开阅读。右上角备注识别文字、段落和整区域目标。

版本：`0.3.0`。运行要求：包含内置 `node:sqlite` 的 Node.js 24 或更高版本。

## 使用流程

1. 在 Codex 对话顶部打开「鹿鸣 · Luming Studio」标签页。首次进入时点击「＋」新建标签页并选择「鹿鸣 · Luming Studio」。在 Luming Studio 首页创建白板或打开已有作品。
2. 在白板上组织文字、便签、图形和 HTML 图解。HTML Region 内部通过标注与 Codex 协作修改，区域整体仍能在白板上移动和调整尺寸。
3. 点击顶部备注图标后选择原生对象、文档段落或 HTML 内部内容，在目标旁填写备注；已有文档文字选区时，沿用该选区。也能从元素浮动条对整个对象备注。HTML 支持点击节点、拖选文字和 Shift 框选。“附加到对话”默认不勾选；勾选后先保存冻结来源，再添加一张上下文附件卡片，不向输入框填写文字，由用户决定何时发送。
4. Codex 在后台读取原始 HTML 和当前版本，以源码为基准，用带版本检查的操作写回同一区域，再读回核对。处理期间可以留在对话里继续输入。
5. 在白板中查看历史、预览差异或恢复版本。恢复会生成新版本，不抹掉后续记录。

多选对象后，可从「更多操作 → 从选区创建分区」套一层带标题的原生分区。原对象的位置、尺寸和相对层序保留，仍可逐一选中编辑。缩小白板时，有足够空间的分区保持可读标题。

画布、HTML 图解和文档的保存问题显示在顶部「操作通知」区。通知中的重试和比较继续使用对应操作。关闭一条带草稿的通知后，可以从「查看通知」入口重新展开处理。

在宿主提供面板状态时，切回聊天可从原白板、视口和选区继续。展开阅读和滚动位置也随该面板保留。

Luming Studio 首页提供作品查找、固定、改名、复制、回收与恢复。数据默认保存在用户主目录下的 `.codexworkbench/luming-studio/`，可通过 `LUMING_STUDIO_DATA_ROOT` 指定数据根目录。

每件作品使用独立的 SQLite 数据库。旧 JSON 作品显示「不受支持」，其回收和永久删除仍由用户控制。

宿主支持上下文更新时，Studio 会上报 `appId:"luming-studio"` 和 `panelOpen:true`。工作台没有选中作品时，作品 ID 和选区可以为空。Agent 可以按需读取当前面板的上下文来定位作品，用作品工具在后台完成读取、修改、回读和导出。访问权限由作品工具检查。用户决定何时切到 Studio 查看结果。`studio_open` 是宿主打开 Studio 标签页时使用的 App-only API。

回收站支持单项永久删除、勾选后批量删除和清空；执行前确认范围。永久删除同时清理该作品的历史、反馈、资源及服务端导出副本，不能恢复；用户自行下载的文件和原始导入文件保持完整。列表和 Grid 共用回收操作与选择状态。

顶部保留版本历史、分享、备注模式与备注列表。分享浮层含分享/导出页签；完整作品备份使用导出页签的 ZIP 项，包含内容、资源、历史、批注与冻结来源；分享凭据和运行状态不打包。在工作台选择“导入作品”恢复为新的作品 ID，不覆盖原作品。ZIP 备份及导入只对房主开放。

画布图钉显示发起人的简称和作者色。重叠图钉显示讨论条数，点开可逐条回到原始位置。备注列表支持「全部」「我发起」和作者筛选，选择一条即可定位并在列表内回复。作者筛选只收窄列表，「显示已解决」同时控制画布和列表。

底部固定选择、平移、文字、分区、便签、画笔、形状和贴纸八个工具，数字1–8依次切换，9进入全局气泡备注；备注模式下按1–8直接切换工具。原V/H/T/A/S/P/R/E字母工具键已移除。输入文字、备注、菜单或普通HTML交互时不拦截数字；HTML标注模式中的非输入区域同样支持1–9。复制、粘贴、撤销等组合键保持通用行为。画笔子菜单包含箭头，形状内提供表格/链接/HTML/文档区域等插入，贴纸内上传图片或视频。成功单次放置后回到选择，文字和便签继续原位输入，也能直接调整尺寸；按空格临时平移。切换到其他工具时隐藏元素编辑浮层，回选择恢复选区。锁定只固定几何位置，保留文字、样式、HTML 源编辑和备注。

建议方案通过房主备注列表提供私人预览、应用和安全撤回；访客只能看到正式应用后的内容。不相交的选项可并用，相交选项切换时先安全撤回旧项；后来被修改的内容不会被旧快照覆盖。

双击分区标题可原位编辑。选中分区后，也可按 F2 或从选区的「更多」菜单选择「重命名分区」。格式工具条会避开标题和输入框。

画布聚焦时按 Ctrl/Cmd+Z 逐笔撤销本次编辑。正在输入时，撤销交给当前编辑器。协作冲突影响撤销目标时会提示涉及的操作和对象，其他编辑仍可提交。

选中元素后可使用“适应选区”或“全屏观看”。全屏只占插件工作区，隐藏编辑工具并聚焦所选内容；HTML 自动进入交互模式，退出后恢复先前模式与视口。观看工具提供当前比例、精确百分比、放大/缩小及“适应全屏内容”，也可切换浏览和临时荧光笔。笔迹只在本次观看中显示，完成后约 3 秒淡出，可立即清除；不写入作品或撤销历史。

## 可选 Diagram Design

Diagram Design 是可选的外部 Skill，不随 Studio 复制或安装。当前 Codex 可使用它时，同一个 Codex 可以按其图种和样式规范生成 HTML，再写入 Studio 的 HTML Region。

没有 Diagram Design 时，基础白板、已有 HTML 内容与手动导入仍可使用。Studio 不把本地某个技能目录的存在当成可调用证明，也不在缺失时声称已使用它生成图解。

Studio 内只有一个中文版业务 Skill：[luming-studio](skills/luming-studio/SKILL.md)。它负责作品、反馈、版本和工具的工作流，不复刻 Diagram Design 的图种库。

按任务读取该 Skill 的参考：

- [Agent 有界读取与局部取图](skills/luming-studio/references/agent-reading.md) · 查找、分页、版本、目标写回和真实视图取图条件。
- [白板表达与布局](skills/luming-studio/references/whiteboard-craft.md)：内容形式、标题、文字、关系、分区、间距、局部清理和人工布局的保留。
- [图片与素描](skills/luming-studio/references/pictures.md)：实物构图、干净绘图、马克笔表达、剖面、分镜、部件标注和 SVG 资源。
- [建议方案与预览](skills/luming-studio/references/ideas.md)：私人建议、预览、应用、互斥、安全撤回与生命周期。
- [对象与协作操作](skills/luming-studio/references/operations.md)：元素、媒体、连线、嵌入状态、视图上下文和共享恢复。
- [白板对象格式](skills/luming-studio/references/whiteboard-format.md)：当前白板字段、操作、媒体资源与可恢复备份。
- [文档区域与段落修改](skills/luming-studio/references/document-regions.md)：块 JSON、统一备注、冻结段落来源与局部修改。
- [HTML 区域与反馈](skills/luming-studio/references/html-feedback.md)：原始内容定位、冻结来源、版本与标注。
- [配色与可读性](skills/luming-studio/references/appearance.md)：界面与内容主题、对比度及中文可读性。

## 标注、共享和权限

标注记录作品和区域引用、源码版本、目标标识、文字或 DOM 摘录以及备注。摘录和截图用于定位；可修改的原始内容由 Studio 工具按引用读取。

MCP App 内的标注通过插件自己的选择层和宿主消息扩展实现，不假定 iframe 具有内置浏览器的顶层 Annotation API。附加草稿与发送消息是两步；局域网访客提交给 Codex 的请求需由本机接收流程处理，不能继承房主的 Codex 登录态。

协作者请求附加备注后，房主的备注列表入口显示待附加数量，并提供一次可直达备注的提醒。附加状态与备注是否解决分别记录：宿主确认插入附件后显示“已附加到对话”，打开列表不会清除待附加数量。失败可重试；宿主已确认而状态回写失败时，当前页面记住确认结果，只重试保存状态。同一内容的请求不会重复插入附件，编辑或回复后可再次请求。宿主成功与状态写入之间关闭页面的情况无法自动判断，请先核对对话草稿。

分享按编辑、评论和查看角色授权，支持仅本机与局域网两种访问范围。本机角色链接可以直接复制，复制不会自动开放局域网；明确开启局域网后，顶部分享按钮显示绿色状态点。支持成员光标和视角跟随，同一成员的多个页面只计为一个人。光标聊天及其 `/` 全局快捷键已移除；正文中的 `/` 用于文档插入命令。

共享链接首次进入需填写姓名，同一白板内不能与其他成员重名。浏览器保存一年期身份凭据，姓名登记独立于访问权限；同一浏览器、同一共享地址再次进入可沿用身份，换浏览器或设备不能仅凭姓名继承权限。关闭分享或重置链接仍会撤销相应旧凭据；房主移除成员后，对方进入明确的失权页面，未提交草稿不会自动发送。房主可在分享面板的“已移除的成员”中选择角色恢复访问，也能用小垃圾桶删除该板的已移除记录及姓名登记；之后对方需打开有效邀请并重新输入姓名。移除前排队请求不会恢复，旧评论、历史作者和其他白板身份保留。在线显示绿色状态点，离线显示多久前来过。链接是访问凭据，请只交给预期参与者。

Agent可显式声明任务工作区、续期和结束；画布显示非阻塞淡色范围与工作动画。点击跟随可查看该Agent的工作区域，手动操作画布会停止跟随；任务结束或过期后清理。工作区提示不会禁止人工编辑，Agent仍避开其他人正在编辑的对象。

HTML导出默认为整块白板的已保存网页内容，原生对象与HTML区域按版面组合，不含协作评论和历史。HTML区域可使用已保存状态与自足脚本，导出后的状态仅保存在当前网页内存；外部网络依赖不会自动打包。单个HTML区域的源码导出与整板网页不同，完整可恢复内容使用ZIP备份。

顶部保存状态根据实际写入显示：完成为绿色、保存中或未保存草稿为黄色、保存异常为红色。共享计时器展开后在画布操作期间保持为完整卡片，可从计时器按钮主动收起。

## 明暗主题

界面与内容分别处理主题。Studio 首次响应宿主主题，之后可用单个日／月图标切换明暗；HTML Region 保留自己的内容配色，不做整图强制反色。默认参考 Diagram Design 的背景、正文、次要文字、强调和连接等语义色，尤其检查暗色下节点填充与文字、连线及标签的对比。

## MCP 工具

| 工具 | 用途 |
| --- | --- |
| `artifact_list` | 查找、筛选并分页列出作品 |
| `artifact_manage` | 创建、命名、固定、复制、回收、恢复、导入备份及导入／移除未引用资源 |
| `artifact_read` | 概要、板内搜索、区域定位、指定对象与段落或任务、明确视图、历史和差异 |
| `artifact_apply` | 带版本检查和幂等标识的批量修改、历史恢复与安全撤回 |
| `artifact_feedback` | 处理批注、显式 Agent 请求及私人建议的预览／选择／撤回 |
| `artifact_share` | 管理本机／局域网分享、邀请链接及成员权限 |
| `artifact_export` | 按对象或区域导出局部 JSON、HTML、SVG、PNG；PNG 支持按世界坐标渲染已保存版本 |
| `artifact_activity` | Agent声明准备／写入／验证阶段，查询或结束具体任务；房主可在界面释放某一任务 |

Agent 先定位，再按对象或范围分页。普通页最多 20 项，精确对象 ID 每次最多 10 个，服务端限制结构化响应字节数。按需取图带来源、范围和版次。整板导出与完整 ZIP 备份从作品界面操作。 [有界读取与取图流程](skills/luming-studio/references/agent-reading.md)

工具 schema 和返回值是接口依据。模型可通过 `artifact_manage action:"asset-import"` 导入用户指定或本次生成的本机媒体绝对路径，使用返回的稳定资源引用；`asset-delete` 会检查当前内容、保留历史、来源和提案，并保留内部回收副本。实时光标、拖动预览和选区由协作服务同步，不为每次界面操作增加模型工具调用。

Agent首次查找作品和空地可不带任务只读；正式工作先用`artifact_activity begin`声明互不重叠的范围，记录返回的`taskId/generation`，并在每次真实内容写入时显式携带。任务有准备、写入、验证阶段：10分钟无活动才过期，2分钟无实质进展会变灰但保留范围，重复查询或心跳不能冒充新进度。任务代次与对象CAS版本不同；人类仍可正常编辑，不需要Agent任务。房主释放后，旧代不能再写，也不能盲目改名重新抢区。

长期MCP连接会在调用前检查本机服务记录，服务地址或凭据变更时重新验证，保持Agent身份和单个服务进程租约，但不会自动恢复已失效的任务代次；失败的写请求不会自动重放。正常关闭只尽力取消该连接明确登记的任务，不为清理启动离线服务。启动页保留后端实际错误。升级插件后需重新建立已加载的旧版MCP连接，页面重试不会替换仍在运行的旧版代码。

## 开发与交付

### 代码检查与排版

开发环境使用 Node 24.11 或更高的 Node 24 版本。`pnpm --filter @codexworkbench/luming-studio lint` 检查插件 `src`、`tests` 与仓库 `tooling` 内的 TypeScript、JavaScript、CSS 和 HTML 源文件。可传入插件内路径，例如 `pnpm --filter @codexworkbench/luming-studio lint src/app/features/whiteboard`，也可传入相对于仓库根目录的 `tooling` 路径。

[ESLint 配置](eslint.config.mjs) 使用 React 官方 `recommended` 规则，并检查命名、控制流、异常处理、代码布局和导入边界。工作台和编辑视图由 Studio 外壳组合，画布代码使用结构比较判断值是否相等。[Oxlint 配置](.oxlintrc.json) 检查 Promise、联合类型分支、未用符号、过时用法和不安全的 React 生命周期，也检查草稿与工具响应入口的危险赋值和类型断言。[Oxfmt 配置](.oxfmtrc.json) 检查同一批文件的排版。`pnpm check` 和 Studio 构建都执行 Lint 与 TypeScript 检查。构建通过这些检查后才写入运行资源。

源码注释一律报错，CSS 和 HTML 中的注释也会阻断构建。

- 代码使用 2 空格、LF、100 列目标行宽、单引号和分号。导入组、顶层类型和函数、连续守卫后的主流程之间留一行。连续守卫成组。
- Props 依次组织输入数据、能力和状态、事件回调。共享协议类型放在 `contracts`。模块内部类型放在主要使用处附近。导入纯类型使用 `import type` 或内联 `type`。样式和初始化导入维持原有执行顺序。
- 圈复杂度最多 20，语句块和类型表达式嵌套最多 3 层。单个判断最多两个 `&&` 或 `||`。当一个函数处理多项职责时按业务步骤拆分，在 JSX 中使用具名事件处理函数。
- 捕获异常时处理已知情况、报告失败或上抛。包装错误使用 `cause` 保留原始原因，Promise 的拒绝走同样的处理路径。
- Studio 工具名从 `STUDIO_TOOLS` 和 `APP_TOOL_NAME` 引用。测试可以用协议字面值核对对外约定。

### 产品与公共层

`runtime/server.mjs` 是 [tooling/build-luming-studio.mjs](../../tooling/build-luming-studio.mjs) 从 `src/server/index.ts` 自动生成的 esbuild 分发文件，包含后端运行依赖；其长度包含打包代码，不能视为业务单体。前端由同一脚本经 Vite 生成 `runtime/app.html`，PNG 渲染另随附 `runtime/resvg.wasm`。业务修改维护下列源码，再统一构建运行资源，不手工修改生成文件。

`src/server/` 负责 stdio MCP 协议、HTTP／SSE 传输、连接鉴权、本机权威服务发现与进程租约。嵌入的 MCP App 通过仅界面可用的 `studio_app_request` 与宿主通信，不直接请求 loopback；该内部传输不增加模型可见的九个业务工具。完整文档、媒体和备份按有界分块传输，写入保留人类作者。Web 页面使用带水位的 SSE，MCP App 使用有界长轮询取得同一增量流；版本保护的轻量对象变化减少无关HTML传输，缺口按精确版本补读，历史失效时读取权威内容。它们共用 `src/core/service.ts`，不另建一套业务存储。

`src/app/shell/` 负责会话、导航与视图恢复。`src/app/pages/` 通过页面入口装配用户功能。`src/app/features/` 分别承载工作台内容管理、白板、反馈、历史、协作和导入导出。

`src/core/` 执行作品权限、版本检查、历史、批注和归档的业务规则，存取能力通过 `src/core/ports/` 声明。`src/infrastructure/` 实现 SQLite、素材、归档、计时持久化和 PNG 渲染，由服务端组合根接入。主题、几何和其他共用计算位于 `src/shared/`。

`src/core/products/` 负责产品注册与白板内容适配，包括内容校验、编辑操作、读取投影、差异、反馈源码快照及导出；白板几何供画布与导出共用。新增产品时，实现并注册后端 `ProductDefinition`（`src/core/products/index.ts`）与前端 `ProductDescriptor`（`src/app/products.tsx`），公共层继续处理版本、权限和协作。当前只注册真实实现的白板，不展示空产品入口。

`src/app/shared/html-region/` 提供 HTML 渲染、元素／文字／区域标注和有限状态桥。`src/app/transport/` 提供 Web 与 MCP App 的客户端、回执解码、协作通道、宿主消息与背景上下文。

HTML Region 默认禁止外部网络资源并保留自身配色。图片、字体等需内联为当前沙箱允许的数据资源，字体提供明确回退；不要直接引用本机路径或依赖 Google Fonts。`window.studioEmbed.load/save/onLoad` 提供至多 64 KB 的 JSON 对象状态桥，保存经过区域版本检查；改 HTML 不附带覆盖旧 state。完整备份不包含安装目录或访问凭据。

区域使用 `sandbox="allow-scripts"` 的 `iframe srcDoc` 渲染副本，保持独立样式与不透明来源；UTF-8 声明位于注入脚本之前。原始源码单独保存，标注、状态和滚动消息校验来源窗口、通道、区域及源码版本。

MCP App 文件导出通过公开 `app.downloadFile` 交给宿主保存，保留中文文件名和原始字节。宿主未声明该能力、拒绝或取消时明确报错。Web 使用浏览器下载设置。服务端组合根向业务服务注入导出副本存取端口。文件适配器在数据根目录的 `exports/` 中按导出 ID 保存副本和下载文件名。单次文件沿用 128 MiB 作品传输预算。

在仓库根目录安装开发依赖后，运行 `pnpm --filter @codexworkbench/luming-studio typecheck`、`pnpm --filter @codexworkbench/luming-studio test` 和 `pnpm --filter @codexworkbench/luming-studio build` 检查与构建；仓库级检查入口仍为 `pnpm test`、`pnpm check`、`pnpm build`。商城运行资源由开发者预构建，终端用户不需要先构建源码。分发使用 Git marketplace，作品 ZIP 是用户数据备份，不是插件安装包。

不要直接修改已安装插件的缓存副本。插件源码、预构建运行资源与用户数据分别维护；安装后需要在目标 Codex 宿主验证入口、消息附件和页面生命周期。

验证结果应区分工具自动测试、界面检查、实际 Codex 宿主、真实双机局域网和 macOS。当前仍未完成真实 Codex MCP App、两台物理设备的 LAN 和 macOS 实测；这些范围不能通过“跨平台 JavaScript”、模拟宿主或单机多页面测试推断为通过。
