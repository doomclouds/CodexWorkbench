# 配色与可读性

在生成 HTML 图解、切换内容主题、修复对比度或导出时按需读取。

Studio 界面跟随宿主或用户选择的主题，HTML Region 可以保留独立内容主题。暗色编辑器里显示一张完整的浅色图解是有效选择；透明背景配深色文字导致文字消失则是显示问题。

## 架构图的默认主题

新生成的系统架构、子模块架构和部署架构图默认使用明亮内容主题。用户明确指定暗色或跟随系统时，按其要求生成。

与 Diagram Design 组合时，在生成要求中明确指定“明亮主题”，并在 HTML Region 源码中固定完整的明亮配色。背景、节点、文字、线条、箭头和标签遮罩一起使用明亮主题的语义色；不能只依赖系统或宿主主题检测，让架构图自动切到暗色。

导入已有图解或局部修改其内容时，沿用原有主题，除非用户要求改变配色。白板界面主题与图解内容主题分别处理。

## 语义配色

下面的默认颜色依据 Diagram Design 的语义色参考，用于给绘图任务提供明确主题，不要求替换用户已有品牌。

| 角色 | 明亮 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `paper` | `#f5f5f5` | `#2d3142` | 内容背景、默认节点填充 |
| `paper-2` | `#ececec` | `#393e53` | 次级表面与分区 |
| `ink` | `#2d3142` | `#f5f5f5` | 正文、主要边线 |
| `muted` | `#4f5d75` | `#bfc0c0` | 次要文字、默认连线 |
| `accent` | `#eb6c36` | `#f08a59` | 重点对象与状态 |
| `link` | `#2e5aa8` | `#6a95d8` | 链接及特定关系 |

节点表面、节点文字、边线、箭头标签和背景应一起考虑。明亮的强调色填充可能仍需深色文字；不能因为当前是暗色主题，就把所有对象上的字都改为白色。

HTML 中尽量用 CSS 变量表达这些角色，并明确背景与前景色。SVG 的 `fill`、`stroke`、标签遮罩和 marker 也要使用对应角色，不能仅改页面 `body`。

## 中文与图解

- 中文正文和关键标签使用可读的中文字体回退，例如 `"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`。没有实际携带或加载字体时，不能承诺所有设备字形和换行完全一致。
- 节点名称、说明、技术值和标题分层。等宽字体用于端口、协议、命令等技术内容，不机械套用到所有中文文字。
- 标签太长时优先换行、加宽或精简表述，不能为了塞进小框把必要中文缩到难以辨认。
- 连接线和标签应避开关键内容。颜色不能独自承担区别；必要时配合文字、线型、箭头或边框。
- 保存原本正常的图解风格。仅修复暗色可读性时，不连带改变内容、排布或用户明确指定的颜色。

## 检查与导出

检查正文、次要说明、节点文字、边线、箭头、标签、选中态和批注标记的实际前景与背景。主题切换后分别查看；不要把浅色检查通过当成暗色也通过。

HTML 区域的演示动画不应使静态画面缺少关键含义。截图和静态导出应有完整可读的状态，减少动态的用户偏好也应得到保留。

导出时沿用用户选择的内容主题和范围。若用户要求适合文档的浅色图，基于同一份源生成明确的导出变体，不悄悄改写正在协作的原区域。
