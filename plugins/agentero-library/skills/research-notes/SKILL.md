# 研究笔记

只在用户要求保存、整理到文件或更新笔记时写入。一般论文问答直接回复，不因生成了有价值的答案就自动落盘。

## 确定目标

- 用 `library_status` 确认 Vault 引用；目标不明确时用 `note_list` 查找已有笔记，必要时结合 `paper_get` 区分独立笔记与论文笔记。
- 用 `note_read` 读取目标内容、存在状态和 revision。缺失文件与空笔记分别处理，不把读取失败当作可以覆盖的空文件。
- 新笔记选择与用户意图相符且不冲突的名称；没有可靠排他创建保证时，不承诺同名文件绝不会发生竞争。

## 编辑与保存

1. 保留用户已有内容、frontmatter 与可核验引用；只更新任务涉及的部分。未读取的论文不添加假引文。
2. 调用 `note_write`，传入读到的版本及明确的 replace／append 行为。它是笔记范围内的公开工具，不接受任意文件写路径。
3. 遇到 `NOTE_CONFLICT` 或 `VAULT_CHANGED` 时保留草稿，重读并比较；不自动改绑新库或盲目重试整篇覆盖。
4. 根据实际保存结果，必要时用 `note_read` 回读，返回笔记引用与本次改动。失败或状态不明时说明尚未确认保存，不把草稿当作已保存笔记。

本插件的版本检查和队列不是跨进程原子 CAS。外部 Agentero／编辑器仍可能在检查与写入之间更改文件；不能承诺并发零丢失，也不通过强制覆盖消除冲突。

Markdown 源码、富文本和预览是同一份笔记的视图；保留表格、公式、代码、任务列表、图片相对路径与内部引用，不把预览HTML写回源码。用户要求重命名时先读取revision，再用 `note_rename`，保留用户选择的目录范围。需要追踪已有引用时可用 `note_links`；不把未扫描到的链接断言为不存在。
