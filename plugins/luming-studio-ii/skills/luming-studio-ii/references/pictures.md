# 图片与素描

绘制或重绘实物、场景、图标、平面图和分镜时使用这份参考。专业图解可组合 Diagram Design，普通插图可以直接完成。

## 一张图应当包含什么

先确定用户需要的是可单独操作的物体，还是一个完整场景。需要分别移动、缩放或删除的物体适合各自成为图片或 HTML 图解，背景和摆在上面的物体也可分开。遮挡、光照和空间关系共同构成场景时，保留完整画面。

图片说明外观。传递、流程、循环和依赖保留在白板的原生连线里；事实、步骤、数值和难以靠外观理解的部件，用靠近对象的说明补齐。风、声、热、光等输入输出，可用少量方向明确的波形或笔迹并附简洁说明。用户明确需要一幅独立插画、一个图标或完整场景时，按该作品自身组织。

主图宽度可从 320 至 480 个画布单位起步，辅助物体约 160 至 260，独立展示的大图约 800。最终根据实际视口、内容和文字调整画幅，并保持图像宽高比。

## 选择载体与提交资源

| 需求 | 载体 |
| --- | --- |
| 已有图片、独立插画和非交互 SVG | 原生图片对象，保留独立移动和裁剪 |
| 可精确定位内部文字或部件的图解 | HTML 图解与内联 SVG，用 `data-studio-id` 给可备注部件分配稳定 ID |
| 投票、计算器、可操作原型 | HTML 图解。需要共同保存输入时使用 [HTML 交互状态](operations.md#html-交互状态) |
| 实拍、位图或参考素材 | 实际取得的授权素材，或当前可用的图像生成能力 |

在白板界面附加图片可同时上传资源并放置可移动对象。能读取用户指定本机文件的入口，也可用 `artifact_manage` 的 `asset-import` 导入白板资源，记录回执里的 `asset.assetId`、`asset.src` 和 `asset.mediaType`。导入资源和放置图片是两个动作。当前 `artifact_apply` 的 `geometry.create` 支持 `html` 等原生对象，原生图片请走界面媒体入口。已导入的资源可按对象载荷能力复用，例如文档图片块的 `props.url`。详见 [媒体与绘图](operations.md#媒体与绘图)。

示例把一个本机制作完成的 SVG 导入白板资源。请替换板 ID、稳定命令 ID 和实际文件路径，随后核对回执。

```json
{
  "action": "asset-import",
  "boardId": "rainwater-board",
  "commandId": "import-rainwater-tank",
  "assetPath": "D:/StudioAssets/rainwater-tank.svg"
}
```

HTML 图解的交互状态和完整源码各有版本。内联 SVG 的全部形状仍以该 HTML 源为事实来源。使用内联脚本和样式。图解沙箱的图片、媒体和字体使用嵌入资源，例如图片或字体的数据地址。普通白板资产的路径要按具体对象的加载能力使用。在实际宿主、LAN 访客和离线导出处分别确认显示效果。

## 先列清楚看得见的东西

动笔前确认主对象、相关对象、关键部件和彼此关系。机械结构、器件、自然物体应体现真实轮廓及必要环境。展示内部原理时可用剖面或局部放大。

一个短计划只需交代每个实物是什么、哪些事实需要文字或框、对象间如何连接、每个实物有哪些辨识部件。外壳接缝、按钮、开口、支架、线缆、屏幕、容器口沿和运动方向通常比装饰更能说明尺度与用途。未知的内部结构、端口和尺寸应以示意表达。

## 干净绘图与手绘表达

优先遵循用户指定的风格。几何图、平面图、电路示意、曲线、图标和标志通常适合干净绘图。用明确的正视轮廓、规整的比例、稳定线宽和克制的颜色表达受控尺寸与关系。区分辅助线和实体边界，图标优先使用少量清晰大形状。精确的比例和位置应保持其实际含义。

解释外观或场景时，可以使用设计素描或马克笔风格。重点在形体、透视和有解释作用的细节。II 中可以在 SVG 或图片素材上落实线条和明暗，旧样式属性本身只作为历史数据处理。

## 马克笔或设计素描的构成

1. **先定形体。** 用整体轮廓建立焦点和一致比例。略高的三分之四视角能同时显示顶面、正面和侧面。用遮挡区别近远，用方向一致的椭圆表现圆口、转轴和弯曲面。
2. **铺主体色块。** 用两三种主要颜色保留亮部。暗面色块可以略出轮廓。独立插画可用较宽、较低的色块托住主体，作为白板中的一个可移动物体时通常只需要主体。
3. **增加同色深浅。** 用受光面、背光面、凹陷和底部表现层次。透明阴影叠在实际会看到的背景上验收，尤其检查暗色模式。
4. **画主轮廓。** 用比细节略粗的线条表达体积、遮挡和主要开口。可从主轮廓约 2.5、细节约 1.2 的线宽比例起步。
5. **补解释细节。** 接缝、螺钉、旋钮、通风口、导线、把手、折痕和屏幕符号使用同一透视。主体约 40 至 60 个形状或笔画、配角约 15 至 25 个的量级，只用于判断图像是否过于简略。
6. **检查阅读。** 轮廓、色块、阴影和标签应共同解释用户关心的部件。删去会争夺焦点的细节。

柔和的蓝、橙、黄、绿、紫和中性灰可作为配色起点，从主色生成深浅层次。品牌任务保留品牌色。深色部件和投影留出背景区别，浅色部件保留可见边界。

## 剖面、分镜与场景

剖面让关键工作部件清楚可辨。用合理的轮廓和色块区分类别，同类部件保持同样处理，名称放在邻近位置。

横向分镜为每格建立边界，保持人物和物体的比例一致，清楚显示动作变化。空间提示保持简练，必要时用序号或简短字幕说明时间顺序。概念插图可从桌面、装配或分类中的真实景象借用道具，由道具承担解释。

## 标签、箭头与坐标

将图片名称和部件说明放在相应位置。原生图片可在外部加文字和短箭头，HTML 内联 SVG 可把文字和 `data-studio-id` 放在对应部件。引线尽量水平或垂直，沿最近的空白边缘布置，预先分配多组标签的位置，避免交叉和盖住关键形状。

新 SVG 的 `viewBox` 建议从 `0 0` 开始并匹配显示宽高比。已有 SVG 若从 `(minX,minY)` 开始，在没有留白、裁剪或旋转且宽高比一致时，设图片的白板位置为 `(x,y)`、显示尺寸为 `(w,h)`。内部坐标 `(u,v)` 对应白板点为 `(x + (u-minX)*w/viewBoxWidth, y + (v-minY)*h/viewBoxHeight)`。存在裁剪、留白或旋转时，按真实渲染变换重新定位。图片移动和缩放后复查纯坐标引线。

## SVG 与资源验证

SVG 使用完整闭合的元素、正确命名空间和 `viewBox`。可以用规范编码的数据地址，重点处理 `#`、`%`、`&` 等字符。作为原生图片加载的 SVG 使用明确的颜色与所需资源，作为 HTML 内联 SVG 则可使用该区域的 CSS 变量。

读取回执并查看实际画面，核对图形、标签、原图与图片资源。LAN 访客和离线导出分别验证。所需字体、图像或样式缺失时，说明已有条件，或在授权范围内补齐资源。

## 组合示例

解释雨水怎样流到花盆时，用收集口或储水桶做主图，阀门、软管和花盆作为辅助对象。标题在上方，一句主旨说明流从哪来、到哪里。原生箭头表示水流，说明框标注过滤、储存和浇灌。

需要一张完整装置图时，把储水桶、管道和花盆在同一场景中表现。需要逐一批注液位、阀门或管道时，使用包含稳定部件 ID 的 HTML/SVG 图解。示意图中的实际容量、压力和效率都以用户提供或已经核对的数据为准。

## 修改一张已有图片

移动时保留资源、裁剪、链接与身份。调整显示尺寸时复查比例、原图和引线。重绘前确认需要替换的是现有图片还是独立新增的版本；并保留用户的手工笔触、可编辑来源和原始清晰度。通过支持的媒体入口替换或放置重绘资源，然后复查与相邻对象及既有链接的关系。
