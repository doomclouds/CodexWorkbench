# 配色与可读性

生成原生文字、含文字的对象、HTML 图解，调整主题和准备导出时使用这份参考。白板外壳可以跟随宿主或用户选择，HTML 图解可固定自己的内容主题。暗色画布中的完整浅色图解以自身前景和背景为一体。

## 架构图的默认主题

新系统架构图、子模块架构图和部署图默认采用明亮内容主题。用户给出品牌、暗色或跟随系统的要求时，沿用指定选择。已有图解的局部修改沿用其主题。

使用 Diagram Design 时，可以从它的浅色样式、语义配色、字体和连线规范开始。HTML 图解明确设置背景、节点、文字、边线、箭头和标签遮罩，确保它们在不同的宿主主题下仍然作为一套图出现。制作跟随系统的变体时，在区域内部同时定义两套颜色。

## 原生文字的默认配色

普通文字、便签、形状、分区标题和连接线标签先使用默认前景。用原生正文的 `TextPayload` 创建文字时可省略 `color`。已有对象只修改本次所需字段，保持已经保存的字色。透明文字继承画布前景，形状和便签在识别到自身的固定不透明填充时选取相应的默认字色。

修改原生外观时，位置样式使用 `geometry.style.patch` 的 `fill`、`stroke` 和 `textColor`。这些字段支持十六进制色值和 `"transparent"`，文字样式修改同时使用读取到的几何和正文版本。用固定品牌色时同时核对表面和文字。透明背景上的固定深色字需要在暗色画布中复查。配色角色名称可以在 HTML 样式中表达，提交 II 原生外观时使用相应色值。

表格正文使用画布的基础表面和前景。表头通过自身填充选择背景，并以 4.5 为表头基础前景对比度阈值计算可读字色。单元格内带颜色的富文本也应单独检查。分区标题位于边界上方，与分区内部的文字分别核对。

透明文字覆在其他对象上时，按实际背景检查可读性。特别关注图片、图解、半透明层以及旋转或交叠的形状。这些对象的背景可能随裁剪、图层或缩放变化。读回本次对象的字色、填充和层级，再查看实际画布。

## 语义配色

下面的参考值适用于新图解或同一张白板中的语义配色。用户已有品牌时沿用它的角色与对比度。

| 角色 | 明亮 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `paper` | `#f5f5f5` | `#2d3142` | 图面背景和默认节点表面 |
| `paper-2` | `#ececec` | `#393e53` | 次级表面 |
| `ink` | `#2d3142` | `#f5f5f5` | 正文和主要边线 |
| `muted` | `#4f5d75` | `#bfc0c0` | 次要文字和默认连线 |
| `accent` | `#eb6c36` | `#f08a59` | 强调对象和状态 |
| `link` | `#2e5aa8` | `#6a95d8` | 链接和特定关系 |

亮色强调填充通常仍适合深色字。将背景、表面、文字、箭头和遮罩一起选色。HTML 中用区域自身的 CSS 变量组织这些角色，给 SVG 的 `fill`、`stroke` 和 `marker` 分配相同语义。

## 中文与图解

- 中文字体可回退到 `"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`。设备实际可用的字体会影响字形和换行。
- 标题、节点名称、说明与技术值使用清晰的文字层级。等宽字体适合端口、协议、命令或数值。
- 长标签优先换行、加宽或简化措辞，同时保留足够的字级。
- 主连线和标签避开关键形状。颜色配合文字、线型、箭头或边框表达类别和状态。
- 仅修复可读性时，保留布局、内容和指定品牌。需要新的对照图时，可基于同一份源制作不同主题的导出版。

## 检查与导出

分别检查正文、次要说明、节点文字、边线、箭头、标签、选中态和备注标记在预期主题中的前景和背景。进行暗色和明亮两套验收时，分别查看画布。

HTML 图解以保存态也能读懂为目标，关键内容在截图、静态导出和减少动态的环境中都应呈现。导出前核对选区或整板范围、内容背景、字体和媒体资源。若用户需要适合文档的浅色图，交付相应的导出变体，保留正在协作的原对象。布局与图面尺寸见 [白板表达与布局](whiteboard-craft.md)。
