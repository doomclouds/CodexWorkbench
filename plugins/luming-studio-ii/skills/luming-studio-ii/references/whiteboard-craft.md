# 白板表达与布局

创建、解释、扩展和整理白板时使用这份参考。用户已经明确的形式、位置和修改范围优先。

## 先决定内容以什么形式存在

读者通常先看整体形状，再逐个读标签。过程用方向，循环用闭环，组成关系用层级或包含，比较用共同维度。为每种关系选能直接表达含义的对象。

| 内容 | 建议载体 |
| --- | --- |
| 独立概念、任务、事实、风险和说明 | 原生文字、便签或形状 |
| 因果、传递、依赖和步骤 | 原生连接线，必要时加标签 |
| 阶段、归属和一组内容的边界 | 原生分区 |
| 在同一维度逐项比较 | 表格 |
| 机器、器件、场所和自然过程中的实物 | 可移动的独立图片，见 [图片与素描](pictures.md) |
| 示意界面和线框 | 文字与形状，实际交互用 HTML 图解 |
| 信息密集的架构、数据可视化和专业图解 | HTML 图解，可组合 Diagram Design |
| 投票、计算器和可操作原型 | HTML 图解，按 [HTML 交互状态](operations.md#html-交互状态) 判断保存需求 |

抽象概念和软件关系通常用原生图形就能讲清楚。解释实物时保留关键部件，用户要求作品本身时直接交付图、草图、场景或可操作内容。

## 层次与文字

新主题用标题和一句主旨建立阅读入口。HTML 图解、文档和分区优先使用自带标题。只有一组对象共享新主题时，才单独放组标题或导语。中文保持自然、简洁、完整。

节点名称、次要解释、数值、协议和技术标签使用不同视觉层级。等宽字体适合技术值。背景资料可放在附近的说明、备注或 HTML 图解中。较长的说明可先给 300 至 400 个画布单位宽度，按字号和中文字符实际换行。菱形、圆形等轮廓里需预留更多空间。

对象名称贴近对象，箭头标签说明方向和布局本身不能传达的关系。省略重复的标签。相同类别尽量使用共同的大小、色彩和轮廓，每一种差异说明类别、重点或状态。一个分区通常适合少量标记，必要时用分区题目、简短图例、文字或线型补充颜色。见 [配色与可读性](appearance.md)。

## 阅读方向、间距与分区

中文技术白板通常由左至右、由上至下阅读，按实际方向对齐节点。时间轴、回路、地图及其他指定逻辑保留自身结构。节点间要给箭头和标签留出专门空间。

可从邻近内容间距约 24、有连线的间距约 64、带说明的跨区关系约 144 个画布单位起步。对齐相连对象的中心或端口，适当换行后仍能读出顺序。六步以上可以考虑分段并标示续接，具体由真实内容决定。

分区标题和内容框一起计算占用范围。常用起点是内边距约 24、上方标题约 28，实际根据字号、宽度、换行和缩放验收。给已有图解添加边框时保留原对象身份、位置、大小和相对层级。多选相关对象后可从「白板操作」选「从选区创建分区」，再确认边界和标题。

### 章节、图组与组内顺序

开画前列出章节、各组的阅读顺序和每组的图解、文档及待办。先读取原板分区、标题、对象边界和锁定位置，再按画布空白规划新增范围。

| 层级 | 默认排法 |
| --- | --- |
| 章节 | 从上到下排列。新主题单独起行、写章节名，并留出大于普通换行的间距。同章换行沿用已有章节名。 |
| 同一章节的各组 | 从左至右排，同行顶部对齐，每行最多三组。第 4 组回到该章节左边界，起点是上一行所有组的最下占用边界加间距。 |
| 组的边界 | 每组使用一个带标题的原生分区，边框置于图解底层。组间距可从组内图间距的约两倍起步，计算时包含分区与对象的外置标题、说明、换行和连线。 |
| 组内内容 | 默认两列，最多三行。主图在左上，其余图按阅读顺序填。文档和 Todo 计入位置，跨列或跨行按实际占用算。放不下时拆成可独立阅读的下一组。 |

组标题下可放简短导语。设计依据、约束或跨图读法需要完整说明时，组末可放可展开的原生文档。本组待办也放在组末，与文档同排时文档在左、Todo 在右。跨组行动放在整板末尾的「后续行动」分区，每条关联真实来源图或文档。

用标题、分区和留白区分普通分组与换行。需要逐列对照上下两行时，可加一条与内容区等宽的细线。用户指定的时间轴、对照结构或专门阅读顺序优先，长流程换行时标明衔接。

例如「启动与装配」可按下表规划。每个单元在实际画布按标题和正文内容留出空间。

| 组内行 | 左列 | 右列 |
| --- | --- | --- |
| 第 1 行 | 启动总图 | 模块入口 |
| 第 2 行 | 装配时序 | 故障分支 |
| 第 3 行 | 设计说明文档 | 本组验收 Todo |

新白板可用约 1500×750 的常见视口构图。内容较多时使用概览与细节分区，按画布实际空白向右或向下延伸。这个画幅是阅读起点，作品随内容扩展。

## HTML 图解的统一画幅

新图解可从 1440×1120 的 HTML 对象和 1280×720 的 SVG 图面起步，留出标题、主旨、图例和简要来源。与 Diagram Design 组合时可使用它的 `doc-wide`。同一组架构、子模块和流程图采用一致画幅；用户指定其他画幅时统一采用该尺寸。

内容超出时优先拆成概览与细节，或把详细源码依据放在可展开说明中。保持可读字号和必要事实。已有图解导入保留原有尺寸；统一尺寸时保留对象身份、位置和内容，复看有无裁切。

## 分区与图解的提交示例

II 的分区类型是 `kind:"section"`。透明分区使用 `section.transparent:true` 和 `appearance.fill:"transparent"`。新图解的 `parentId` 指向分区的实际对象 ID，所有 `geometry` 使用白板世界坐标。

下面是同一项 `artifact_apply` 的 `operations`，依次创建分区与第一张 HTML 图解。执行前按照实际白板空白确定范围和正式 HTML，在包含两者的授权矩形内取得 `artifact_activity` 返回的 `taskId` 与 `generation`。完整写入与版本规则见 [操作语义](operations.md#批量与并发)。

```json
[
  {
    "geometry": {
      "create": {
        "object": {
          "objectId": "release-diagrams",
          "kind": "section",
          "label": "发布流程",
          "geometry": { "x": 160, "y": 180, "width": 1488, "height": 1168 },
          "geometryVersion": "0",
          "appearance": { "fill": "transparent" },
          "section": { "transparent": true }
        },
        "initialPayload": { "payloadVersion": "0", "text": { "text": "发布流程" } }
      }
    }
  },
  {
    "geometry": {
      "create": {
        "object": {
          "objectId": "release-overview",
          "kind": "html",
          "label": "发布总览",
          "parentId": "release-diagrams",
          "geometry": { "x": 184, "y": 204, "width": 1440, "height": 1120 },
          "geometryVersion": "0"
        },
        "initialPayload": {
          "payloadVersion": "0",
          "embed": {
            "title": "发布总览",
            "html": "<!doctype html><html lang=\"zh-CN\"><body><main data-studio-id=\"overview\"><h1>发布总览</h1><p>提交变更、核对结果、完成发布。</p></main></body></html>"
          }
        }
      }
    }
  }
]
```

## 新增、扩展与关联内容

先查同一主题是否已经在白板上。完善或改变表达时以原区域为基准，在既有组内优先使用顶部标题与边框以内的空位。需要新组时沿该章节最后一行继续排版，满三组后按该行最低边界向下换行。把已有组、标题、连线和锁定位置保留为规划边界，必要时另找可用位置。

添加图片、表格、链接或图解时一起计算标题、说明和对象宽高。链接卡片通常比小节点宽。重用已有合适引用，作品链接使用 Studio 返回的稳定地址，要求本地文件时交付实际导出物。

## 修改与清理

修改前读取当前目标、几何版本和正文版本。人的布局可能承载尚未写出的思路，保留对象身份、手工分组、文字、颜色和未涉及区域。按任务检查同一名称的重复标签、由数值推出的说明、关联步骤和连接关系的直接影响。

清理时优先处理真实遮挡、溢出、拥挤、相互矛盾的连接及不一致。只更新所需位置或尺寸，移动整组时考虑组员、分区后代、连接线、贴纸和备注锚点。要求修改图片内部部件时，可重绘或修改该 HTML 图解的源码。独立原图也应保持可引用。

写前检查本对象和祖先分区的锁定，以及协作者的实际编辑状态。位置锁定需要遵守，例如移动、缩放、旋转、裁剪和删除前确认权限。能原位修改的正文、样式和源码按本次任务局部更新，保留未涉及的数据。服务端关于几何、正文和范围的检查以实际回执为准。失败时报告具体对象和原因，保留现场并重新核对。

## 讨论、建议与实施

用户明确要把解释、比较或梳理落实到白板时，完成授权范围内的更新。用户在比较改法或评估可行性时，先按 [建议方案与预览](ideas.md) 提供取舍，保留接下来的选择空间。

已经明确的排版和编辑直接完成。遇到会实质改变业务含义、编辑范围或产物的歧义再澄清。新建已获授权的白板及时保存并打开，做好必要步骤、标签和关系。

## 完成与验证

分别验证写入回执、实际视觉和交互行为。字段接受说明命令可提交，视觉可读性通过查看实际画布确认，交互通过操作相应对象或导出测试确认。普通修订核对受影响的区域，复杂重排、图解脚本和主题变化增加相应的验收。

在本次主题和缩放档位查看完整换行、自带标题、相邻对象和必要连线。保留有含义的包含和叠放，修正意外遮挡、裁切和锚点错位。最后让用户知道具体改动位置、关键假设、保存结果和实际验收范围。

成套图解写入后按回执重读对象 ID、分区归属和几何，再在整板全览与组内阅读档位分别验收。确认同行顶部对齐、第 4 组回到左边且避开上一行底边、新章节有标题和额外留白。检查分区标题、边线和内容都可辨认，并实操作品中的原生文档与 Todo，确认两者各自可读、可操作。
